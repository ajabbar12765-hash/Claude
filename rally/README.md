# RALLY — landing page

Single-page, scroll-driven landing page for RALLY king coconut water. Plain HTML,
CSS and JavaScript — no build step, no framework, no npm install. Open `index.html`
and it runs; drop the folder on any static host and it deploys.

Built against the Upwork brief "AI Website builder"
(`https://www.upwork.com/freelance-jobs/apply/Website-builder_~022088013002359563584/`,
posted 13 Aug 2026, $500 fixed).

## Two treatments, same content

Both are complete, tested and deployable. Same seven beats, same brand palette,
same conversion and analytics wiring — they differ only in how the stage is lit.

| | Path | Look |
|---|---|---|
| **Cinematic** | `/` (`index.html`) | Dark keynote showcase. Near-black stage, one accent spotlight per beat (cobalt → yellow → coral, rotating), product lit in a pool of its own light, chapter counter in the bar. Inter throughout, tight and large. |
| **Editorial** | `/light/` | Warm white base as the brief words it, cobalt/yellow/coral washes, Fraunces serif headlines, two deep-cobalt beats for contrast. |

The brief asks for a "white base", which the editorial version takes literally;
the cinematic version reads that palette as stage lighting on a dark room
instead. Pick one to lead with — both use the same `CONFIG` block, so whichever
goes live is configured the same way.

## 2. How to make basic content updates

**Text.** All copy is written directly in `index.html` — find the sentence, change
it, save. Nothing is generated by JavaScript. Each beat is one `<section>` with an
`id`, in the order it appears on the page.

**Anything that needs a key, a link or a list** lives in one block at the top of
`main.js`:

```js
const CONFIG = {
  klaviyo:   { companyId: '', listId: '' },   // public API key + list ID
  mailchimp: { actionUrl: '' },               // or the embedded form's action URL
  ga4MeasurementId: '',                       // 'G-XXXXXXXXXX'
  metaPixelId:      '',                       // '123456789012345'
  stockists: [
    // { name: 'Erewhon', area: 'Silver Lake, LA' },
  ],
  buyOnlineUrl: '',
  wholesaleUrl: '',
  tradeEmail: '',
  instagram: '',
};
```

Every field degrades cleanly when left empty:

- **No email provider** → the form still validates and confirms, and says plainly
  that nothing was stored. A demo never implies a signup that did not happen.
- **No analytics IDs** → no tracker loads at all. No stray requests, and nothing
  that would require a cookie banner.
- **No stockists** → the "stockists at launch" line stays; add entries and the list
  replaces it.
- **No buy/wholesale/trade/Instagram link** → that button or link is hidden rather
  than pointing nowhere.

**Colour.** Every colour is a token at the top of `styles.css` (`--cobalt`,
`--yellow`, `--coral`, `--paper`). Per-beat accents are set inline on each
`<section>` as `--accent` / `--accent-2`.

**Before launch:** replace `https://rally.example.com/` in `index.html` (canonical
+ JSON-LD), `robots.txt` and `sitemap.xml` with the real domain, and regenerate
`assets/og.png` if the hero copy changes.

## 3. What is the client's, and what is a placeholder

The brief says brand assets exist — palette, logo, product photography/illustration
direction. The palette is applied. The other two had not been shared, so:

| Placeholder | Where | Swap by |
|---|---|---|
| Wordmark (circled R) | `#badge` symbol in `index.html`, `assets/favicon.svg` | Replace the paths with the real logo |
| Glass bottle artwork | `#bottle` symbol in `index.html` | Replace each `<use href="#bottle"/>` with the product shot; sizing lives on `.bottle` |
| King coconut artwork | `#thambili` symbol | Same |
| Bottle shape and label layout | `#bottle` | Drawn to the brief's description, not to a photo of the real bottle |

**Deliberately not on the page:** nutrition figures, price, ship date, named
stockists, reviews or testimonials. None were supplied, and inventing them on a
real brand's page is not a risk worth taking. The stat row uses only what follows
from the brief's own claims — 1 ingredient, 0 added sugar, 0 preservatives.

## 4. Structure

```
index.html      cinematic build — content, SEO metadata, JSON-LD, SVG symbols
styles.css      cinematic — tokens, layout, scroll choreography
main.js         cinematic — CONFIG block, reveals / progress / analytics / form
light/          editorial build — same three files, shares the assets below
fonts.css       @font-face rules for self-hosted type
assets/
  fonts/        Fraunces (variable, 400–600) + Inter 300–600, latin subset
  favicon.svg
  og.png        1200×630 share card, rendered from the page's own hero
robots.txt
sitemap.xml
vercel.json     static deploy + cache headers
```

Beats in order: hero → the label → the source → glass → certifications → where to
buy → signup. Editing copy means editing the `index.html` of whichever build you
ship; the two are independent files, so a change in one does not touch the other.

## 5. Checked in a real browser

Both builds, Chromium at 390 / 1280 / 1440 px:

- No horizontal overflow, no section spilling past the fold, no console errors.
- Body text contrast 18.6:1 on the cinematic build; 7.4:1 light / 14.8:1 deep on
  the editorial build. Primary button 4.7:1 (WCAG AA needs 4.5:1).
- With `CONFIG` empty, zero third-party requests leave the page.
- Form validates a malformed address inline, confirms a good one, and moves focus
  to the confirmation.
- All motion — reveals, float, scroll-snap, the drawn map line — stops under
  `prefers-reduced-motion`. Touch targets are 44 px or larger.
