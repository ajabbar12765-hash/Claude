# Baked and Batched — website

A single-page, scroll-driven showcase site. Plain HTML, CSS and JavaScript — no build
step, no framework, no npm install. Open `index.html` and it runs.

---

## 1. Before it goes live — fill in `main.js`

Everything the business needs to set lives in one block at the top of **`main.js`**:

```js
const CONFIG = {
  whatsapp:  '923212008851',   // set — +92 321 2008851
  instagram: '',               // STILL NEEDED — handle without the @
  city:      'Karachi',        // set
  lead:      '48 hours’ notice',
};
```

The WhatsApp number is in and all 11 order buttons are live. If it ever needs changing:
country code + number, digits only, no `+`, spaces or dashes — `0300 1234567` in Pakistan
becomes `923001234567`. If the field is ever emptied, every order button renders dimmed
and inert rather than linking somewhere broken.

`instagram` is still blank, so the Instagram buttons are hidden. Add the handle and they
appear in the order section and the footer automatically.

Each button opens WhatsApp with its own message pre-written — the flavour buttons say
which flavour, the box buttons say which box — so orders arrive already labelled.

## 2. Structure

```
index.html      all page content and copy
styles.css      design tokens + layout
main.js         CONFIG block, then scroll behaviour
fonts.css       @font-face rules for the self-hosted fonts
assets/
  cookies/      cut-out product shots (.webp served, .png fallback)
  fonts/        Playfair Display, Inter, Parisienne — latin subsets
  logo-badge.png, favicon.png
```

Content is written directly into `index.html`, not generated by JavaScript, so the page
still reads correctly for search engines and with scripts blocked.

## 3. Where the prices came from

Two sources disagreed, so they were reconciled into one consistent structure:

- The **2022 menu card** gives Classic Rs. 250 each / Premium Rs. 350 each, and boxes at
  Rs. 1,500 (6 classic), Rs. 2,100 (6 premium) and Rs. 3,000 (12 classic).
- The **brief** gives Rs. 3,000 per dozen and Rs. 500 per NYC Style cookie.

Rs. 3,000 per dozen matches the menu's box of 12 classic exactly (250 × 12), and
Rs. 1,500 / Rs. 2,100 match their per-cookie rates too, so the two sources agree on the
classic tier. NYC Style at Rs. 500 is carried in as a new signature tier.

**One thing does not reconcile:** the brief prices oatmeal at Rs. 3,000 per dozen, but
the menu lists oatmeal as *Premium* (Rs. 350 each = Rs. 4,200 per dozen). The site
currently follows the menu's tiering. Confirm which is right before launch.

Prices appear in `index.html` in three places: the flavour chapters (`.eyebrow`), the
menu tier tags (`.tag`), and the box cards (`.box__price`).

## 4. Design

Colours and type were taken from the client's own logo, sticker and menu card:

| Token | Value | Source |
|---|---|---|
| `--cream` | `#FBF7F5` | sticker background |
| `--blush` | `#E8D5CF` | the circle in the logo |
| `--rose-text` | `#96574B` | menu script, darkened to pass contrast |
| `--ink` | `#191512` | logo lettering |

- **Playfair Display** — headlines
- **Inter** — body text and the `BAKED / BATCHED` lettering
- **Parisienne** — the script `and`, matching the logo and the menu's section headers

Each flavour chapter carries its own accent colour, set inline on the `<section>` as
`--accent`, `--glow` and `--glow-2`. Changing those three values re-lights the whole
chapter — background wash, ghosted headline and all.

Fonts are self-hosted, so the page makes **no third-party requests at all**. Nothing to
break if a CDN goes down, and no visitor data leaves the host.

## 5. Photography

The supplied photos had their backgrounds shot in (powder blue, slate, cream, white).
Each cookie was masked out to a transparent PNG so it floats in the section lighting
instead of sitting in a visible rectangle.

Served as WebP (~60–100 KB each) with PNG fallback via `<picture>`. Every `<img>` carries
explicit `width`/`height` so nothing shifts as the page loads.

The flat lay in the box section (`assets/box-flatlay.jpg`) is used as a framed photo
rather than a cut-out — it is there to show the blush branded box, so the setting is the
point.

**A note on resolution.** The first set of photos came in at ~1125px wide; the later set
at ~740px. The Nutella cut-out in particular is only 329px across after masking, so its
display width is capped to avoid visible upscaling. Higher-resolution originals of any
of these would let the cookies run larger on screen.

To swap in a new photo: cut it out on transparency, export `.webp` + `.png` into
`assets/cookies/`, and update both the `srcset`/`src` and the `width`/`height` on that
`<img>`.

## 6. Motion

Scroll choreography is hand-written in `main.js` — no GSAP, no scroll library.

- **Chapters** — each cookie rises, scales up, holds, then drifts out as you scroll past.
- **Depth** — background washes move slower than the scroll, foreground cookies faster.
  Progress is measured against the parent chapter, so every layer rests exactly where it
  was authored when its chapter is at rest.
- **Reveals** — one `IntersectionObserver`, unobserved after firing once.

All updates are batched into a single `requestAnimationFrame` off a passive scroll
listener. Under `prefers-reduced-motion: reduce`, animation is skipped entirely and
everything renders in its final state.

## 8. Hosting

Static files — any host works, with no build step. Keep the `assets/` folder alongside
`index.html`; every path in the site is relative.

### Vercel (recommended — auto-deploys on every push)

`vercel.json` is already committed, so the framework, caching and security headers are
set on import. In Vercel: **Add New → Project → import this repo**, then set

- **Root Directory:** `baked-and-batched`
- **Framework Preset:** Other
- **Build Command:** none

Fonts are cached for a year (they never change), images for a week, CSS/JS for an hour
so edits go live quickly.

### Netlify Drop (fastest way to show the client)

Drag the `baked-and-batched` folder onto <https://app.netlify.com/drop>. Live in about
thirty seconds, no account needed for a first look.

### A note on deploying by API

The site carries ~5 MB of binary assets (fonts and photography). Push-based tooling that
inlines file contents in a single request is not a practical channel for it — connect the
git repo instead, or drag the folder. Nothing about the site needs changing to deploy; it
is the upload method that has to suit the payload.
